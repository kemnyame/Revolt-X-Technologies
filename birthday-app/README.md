# Revolt Staff Birthdays

A separate staff birthday management application using the supplied Revolt dashboard design. The repository's website `main` branch is unchanged. This app lives only on the `revolt-staff-birthdays` branch under `birthday-app/`.

## Features

- Secure admin sign-in, password change, Postgres-backed sessions, access-controlled exports.
- Staff creation/editing/deactivation, searchable directory, department filters, privacy opt-out.
- Today's birthdays, calendar, next 30 days, pending greetings and congratulation messages.
- Export pending birthdays or all staff to Excel, Excel template, validated Excel import with upsert by Staff ID, import history.
- Leap-day birthdays observed on 28 February in non-leap years; Accra/UTC calendar dates.
- Responsive desktop, tablet and mobile layout adapted from reference.

## Running locally

```sh
cd birthday-app
npm install
DATABASE_URL='postgresql://...' ADMIN_EMAIL='admin@example.com' ADMIN_PASSWORD='set-a-long-unique-secret' npm start
```

At startup the service creates missing tables and the first admin only if none exists. `ADMIN_PASSWORD` must be at least 12 characters. Remove the bootstrap password environment variable after the first successful login; it is never rendered to the browser. To run tests use `npm test`.

## Render deployment

Runtime Node 22, region Frankfurt, build command `cd birthday-app && npm install --no-audit --no-fund`, start command `cd birthday-app && npm start`; service health route `/health`. Set `DATABASE_URL` to the private Neon connection URL, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `NODE_ENV=production`. Use a dedicated web service bound to branch `revolt-staff-birthdays` rather than the existing Revolt website service. The database `revolt_birthdays` belongs to the new Neon project.

## Excel columns

**Exactly seven columns**, in this order: **Staff ID, Name, Number, Birthday, Department, Job Title, Email**. The Add Staff form, directory, blank Excel template and exports use the same fields. Number is a contact phone number; store it as text in Excel to preserve leading zeroes. Birthday supports DD/MM/YYYY, DD/MM (unknown year) or a genuine Excel date. Staff ID, Name and Birthday are required. Staff ID uniquely identifies a record; importing an existing Staff ID updates that employee instead of creating another. Existing employees retain their inactive/celebration-privacy settings during reimport. Staff ID must be supplied in the file; it is not autogenerated.

## Pending birthday Excel export

The **Export pending birthdays** button exports the seven standard staff columns **plus two report-only fields**:

- **Upcoming Birthday Date**: actual forthcoming celebration date stored as a sortable Excel date (e.g. 28 Oct 2026), not the employee's date of birth.
- **Birthday Reminder**: plain-English countdown, showing `Today`, `Tomorrow`, or `In 3 days` (depending on the days remaining).

These fields only appear in the pending-birthdays report. The standard staff export and the import template remain seven columns. The report respects the configured reminder window and excludes birthdays already marked celebrated.

## Supported upload and download formats

The **Import file** action accepts **.xls, .xlsx, .csv, and .pdf** files, maximum 5 MB and 2,000 staff records per upload. The file must contain `Staff ID`, `Name`, and `Birthday` columns and may include `Number`, `Department`, `Job Title`, and `Email`. Re-importing by Staff ID updates that staff record while retaining inactive/celebration privacy preferences. Uploaded phone numbers are handled as strings to retain Ghanaian leading zeroes and international `+233` prefixes.

PDF imports require selectable text in a readable table; scans and images are not processed by OCR. For the most reliable bulk upload, use XLSX or CSV. Errors are shown per invalid row.

Both **Export Pending Birthdays** and **Export All Staff** allow **XLS, XLSX, CSV and PDF**. The pending report includes `Upcoming Birthday Date` and `Birthday Reminder` (e.g. `Today`, `Tomorrow`, `In 3 days`). The seven-column standard template remains XLSX.

## Mobile, tablet and browser branding

The layout supports phones, tablets and desktop screens. On narrower screens, the side navigation opens as an accessible drawer and the staff/admin/history tables become labeled information cards rather than unreadable wide tables. The application ships with a custom Revolt favicon and web-app manifest for browser tabs and home screens, and contains no external chat links or chat widgets.

## Security notes

This is an admin-managed standalone service, not automatically connected to Revolt OS staff authentication. Do not make it publicly editable. Use a strong secret, enable Render managed HTTPS, and ensure your staffing and data privacy policies permit birthday information to be stored. Email sending is not configured; sharing birthday wishes opens the administrator's email client. In-app notifications are generated from stored staff records. Only administrator-managed data is shown. Sample employees already seeded in Neon have DEMO-prefixed Staff IDs and should be replaced with authorised real records before production use.
